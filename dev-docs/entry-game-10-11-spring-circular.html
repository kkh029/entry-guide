10·11편 추가 — 스프링·진동 · 원운동

작성일 2026-06-02 대상: docs/entry-game-10-spring.html · docs/entry-game-11-circular.html 신규 + 9편 강등 + 공통 배선

후속 물리 주제 후보 6·7순위 — 스프링·진동(후크의 법칙·복원력)과 원운동(구심력) — 을 두 편으로 추가했다. 사용자 설계 의도에 따라 탄성을 먼저 쓰고 원운동이 그것을 인용하도록 구성했고, 그 인용의 물리적 근거는 “스프링의 복원력 = 원운동의 구심력”(둘 다 중심으로 당기는 힘)이다. 11편이 새 마지막 편이 되어 9편을 중간 편으로 강등했다.

TL;DR
  • 물리 다리: 10편의 복원력(늘어난 만큼 중심으로 당김, F=k·x)을 11편에서 구심력으로 그대로 인용 — “고무줄로 공을 돌리면 그 당기는 힘이 곧 구심력”.
  • 10편 스프링·진동(세이지 --c10 #5f8d7e·.c-spring): 후크의 법칙·복원력·진동·감쇠. 5편 튕김(닿는 순간 ×-0.7)과 대비(늘어난 내내·거리 비례). 데모 = 당겼다 놓는 수직 스프링.
  • 11편 원운동(테라코타 --c11 #c0744a·.c-circular, 새 마지막 편): 4편 cos·sin 재사용해 각도+=회전속도 → x=반지름×cos·y=반지름×sin. 데모 = 공전 + 🪢 줄 놓기 → 접선 직진(3편 관성).
  • 정확성 가드: 선형 스프링 중심력은 일반적으로 타원이라, 11편 기본 구현은 운동학(각도 증가)으로 항상 깔끔한 원 — “현실 타원/나선 vs 게임 원”을 .tip.real로 명시. 힘 기반 궤도는 ⭐도전(10편 코드 x·y 양축).
  • 로컬 프리뷰 검증 완료 — 블록 SVG 10편 26·11편 39·콘솔/JSON 에러 0·데모 RAF 동작·중첩 cos/sin 블록 폭 490px<736 컨테이너·네비 9→10→11→index.

개요

1~9편은 대부분 직선 운동(이동·가속·낙하·발사·충돌·비탈)을 다뤘다. 10·11편은 시리즈를 주기적·회전 운동으로 확장한다. 두 주제는 dev-docs/next-steps.md에 “스프링·진동(6) → 원운동(7)” 후보로 이미 적혀 있었고, 5편 「튕김·탄성」이 충돌 반사만 다뤘기에 스프링(지속 복원력)과 개념이 겹치지 않는다.

사용자의 핵심 통찰은 “두 운동은 연관이 있고, 탄성을 먼저 쓰고 원운동이 그것을 인용하면 좋겠다”였다. 이는 구심력 = 복원력이라는 다리에 정확히 대응한다(인용 방향이 10편→11편이라 운동학적 ‘그림자=SHM’ 연결이 아닌 ‘중심력’ 연결이 자연스럽다).

설계 다리 — 복원력 = 구심력

하나의 힘, 두 가지 이름

스프링이 늘어나면 중심(기준점)으로 당긴다(복원력). 물체가 옆으로 흐르는 동안 그 당김이 계속 작용하면, 직진하려던 경로가 안쪽으로 휘어 원이 된다 — 그 중심 방향의 힘이 구심력이다. 머리 위로 고무줄에 매단 공을 돌리는 장면이 두 편을 잇는다.

5편 튕김 vs 10편 복원력

10편 §4의 .cmp 비교 박스로 명시한 차별점(5편과 개념이 겹치지 않음을 학습자에게 직접 보여줌):

🏀 튕김 (5편)

  • 부딪히는 순간에만 한 번
  • 속도 방향을 뒤집음 (×-0.7)
  • 힘 크기는 거리와 무관

🪀 복원력 (10편)

  • 늘어난 내내 계속
  • 항상 중심으로 당김
  • 늘어난 만큼 세게 (거리 비례)

설계 결정

  1. 순서: 탄성 먼저 → 원운동이 인용 사용자 지정. 인용 방향이 10→11이므로 “복원력 = 구심력”(중심력) 연결이 자연스럽다. 역방향(원운동의 그림자 = 단진동)은 11편에서 짧은 ⭐보너스(cos·sin 사촌)로만 언급.
  2. 11편 기본 구현 = 운동학(각도+cos·sin), 힘 기반은 ⭐도전 선형 중심력은 일반적으로 타원을 그린다(완벽한 원은 속도·반지름이 딱 맞을 때뿐). 그래서 “항상 깔끔한 원”이 필요한 기본 구현은 반지름 고정 + 각도 증가로 하고, 진짜 힘으로 도는 궤도(10편 코드 x·y 양축)는 ⭐도전으로 분리 — 물리 개념 ↔ 엔트리 구현 분리 원칙(D-4)과 일치.
  3. 색: 세이지(c10) + 테라코타(c11) 기존 9색·초록(--green)·골드와 충돌 없는 두 색을 사용자 확정. 보라 계열(c3/c8/c9)이 붐벼 원운동을 그쪽으로 두지 않고 따뜻한 테라코타로.
  4. 제목: 「스프링·진동」 5편 「튕김·탄성」과 ‘탄성’ 중복을 피하고, 프로젝트 로드맵(index .coming·next-steps)이 이미 쓰던 이름과 일치.

정확성 가드

현실 vs 게임 — .tip.real로 명시
  • 11편 구심력: 현실의 고무줄/스프링 힘으로 도는 물체는 보통 타원·나선(딱 맞는 빠르기라야 원). 게임은 반지름 고정 + 각도 증가로 항상 원.
  • 11편 ⭐도전(힘 기반): x·y 양축에 (중심−현재)×k를 더하는 방식은 처음 빠르기에 따라 타원이 됨 → 그래서 기본은 운동학임을 다시 짚음.
  • 10편 후크의 법칙: 현실 F=k·x(정확한 비례) ↔ 게임 “(기준위치−지금위치)에 탄성계수를 곱한 만큼 속도에 더한다”로 근사.
렌더러 제약 (기존 이슈 재확인)

renderer.js의 note는 .entry-code 최상위 블록에만 표시되고, 계속 반복하기 같은 C블록 자식 블록의 note는 누락된다. 두 편 모두 반복문 내부 줄별 설명은 블록 뒤 산문 .tip(“🔬 반복 안 세 줄이 …”)으로 처리했다. 중첩 cos/sin·복원력 reporter는 데스크톱에서 폭 490~501px로 736px 컨테이너에 들어가나, 좁은 모바일에선 가로 초과(기존 편들과 동일, 알려진 한계).
