11편 2단계(구심력) 섹션의 모드 토글 데모(직선 진동↔원운동을 번갈아 보여주던 demoCanvasLink11)를, 원과 스프링을 한 화면에 동시에 띄우고 도는 공을 위아래 축으로 투영(그림자)하면 그게 곧 스프링 진동임을 가로 점선으로 증명하는 데모로 교체했다.

TL;DR
  • 토글 → 동시 투영: 한 번에 한쪽만 보이던 .mode-pick 토글(force 적분 vx+=K·(cx−bx))을 제거하고, 왼쪽에 도는 공·오른쪽에 매단 스프링을 항상 같이 그린다.
  • 등속 각운동(각도 기반)으로 전환: angle += omega, by = CY + R·sin(angle). 원이 항상 깔끔하고, 추의 y를 공의 by와 정확히 동일하게 두어 가로 점선이 수학적으로 수평이 된다.
  • 그림자 증거: 공→추 가로 점선 + 가운데 세로 기준선 위 그림자 점으로 "두 높이가 항상 같다"를 시각화. 4단계 보너스 팁("도는 공의 그림자는 스프링")을 글이 아닌 실제 데모로 뒷받침.
  • 주변 카피 정합: .tip.real(기존 '힘기반 타원' 설명)을 "원운동 하나에 좌우·위아래 스프링 둘이 숨어 cos·sin은 사촌 / 게임은 각도만 키워 한 코드로 원도 스프링도"로 재작성. 4단계 보너스 팁에 "위 2단계 데모에서 봤죠?" 포인터 추가.
  • 회전속도 슬라이더(demoOmL11, Demo 1 패턴 재사용) 추가로 "각도 += 회전속도" 핵심 개념을 손으로 체험. 토글 전용 dead CSS(.mode-pick 3블록) 제거.
  • 개념 보강(추가 피드백): 페이지에 빠져 있던 핵심 정의 — 원운동 = 직진(관성) ⊥ 구심력이 직각(90°)일 때의 운동 — 을 2단계 📐 tip + 3단계 '빠르기 일정 이유' + .goals 항목으로 추가. 힘이 직각이라 빠르기는 그대로·방향만 틀고, 나란하면 10편 스프링 직선 진동이 됨(스프링↔원 모티프 통일).

function ballPos(){

  return { x: CX + R*Math.cos(r), y: CY + R*Math.sin(r) };
}
function loop(){

개념 보강 — 원운동 = 직진 ⊥ 구심력(직각)

데모 교체 후 사용자가 "원운동에 대한 설명도 부족하다 — 직진으로 앞으로 가는 힘과 중앙으로 당기는 힘이 수직(직각)일 때 일어나는 운동이라는 설명이 없다"고 지적. 실제로 페이지는 구심력(중심으로 당기는 힘)과 관성(직진)을 각각 다뤘지만, 그 둘이 직각으로 만날 때 원이 된다는 정의가 빠져 있었다. 균등 원운동에서 속도(velocity)와 구심력은 정확히 90°이며, 이 직교성이 곧 "빠르기는 그대로, 방향만 바뀜"의 원인(수직 힘은 일을 하지 않음 → 속력 불변)이다.

위치추가 내용
.goals 🔬"원운동 = 가는 방향 ⊥ 당기는 힘 (직각일 때!)" 항목
2단계 (📐 tip)앞으로 가려는 방향(직진·관성) ⊥ 중심으로 당기는 힘(구심력) = 원운동. 힘이 직각이라 빠르기는 안 건드리고 방향만 틂. 나란하면 10편 스프링 직선 진동(같은 힘, 처음 방향이 직각이면 원·나란하면 직선)
3단계 (문단)"왜 빠르기는 일정한가" = 힘이 가는 방향과 직각이라 앞으로 밀지도 뒤로 막지도 않음

이 보강은 페이지의 스프링↔원 모티프와 자연스럽게 맞물린다 — 같은 '중심으로 당기는 힘'이라도 처음 가는 방향과 힘의 각도(직각 vs 나란함)가 원과 직선 진동을 가른다는 통일된 그림을 글로 명시.

벡터 시각화 — 두 힘을 데모에 화살표로

글 보강 후 사용자가 "그 두 힘(안으로 당기는 힘·앞으로 가려는 관성)을 데모에서도 표시해 달라"고 추가 요청. 1단계 메인 원운동 데모(demoCanvas11)에 두 벡터 화살표를 그렸다.

  • 🔵 관성(속도): 접선 방향 (-sin r, cos r) — 도는 중에는 진행 방향, 줄 놓은 뒤에는 정규화한 (vx, vy). 항상 표시.
  • 🔴 구심력(안으로 당기는 힘): 중심 방향 단위벡터 — mode==='orbit'(줄이 붙어 있을 때)에만 표시.
  • 공용 arrow(sx,sy,ex,ey,color)(머리 포함)·tag(x,y,text,color)(흰 배경 라벨) 헬퍼 추가, drawForces()를 render() 끝(공 위)에서 호출.

release 연동: 줄 놓기를 누르면 mode='released'가 되어 🔴 구심력 화살표가 자동으로 사라지고 🔵 관성만 남아, 공이 그 방향(접선)으로 곧장 날아가는 3편 관성을 시각적으로 확인시킨다(별도 분기 없이 기존 mode 플래그 재사용). 두 화살표는 모든 각도에서 직각(dot=0 수학 검증), 라벨은 캔버스 밖으로 나가지 않음(off-canvas 0px 검증). 1단계 .try-hint도 두 화살표·줄 놓기 설명으로 재작성.

화살표 길이를 물리량에 비례 — 회전속도·속도·힘의 관계 시각화

화살표를 그린 뒤 사용자가 "회전속도와 당기는 힘·앞으로 가는 속도 사이의 연관관계가 보여야 한다"고 추가 요청. 고정 길이였던 두 화살표를 실제 물리량에 비례하도록 바꿨다.

화살표물리량회전속도 2배 → ?
🔵 속도(관성)v = 반지름 × 회전속도 (radius·wr)2배 (비례)
🔴 구심력(당기는 힘)a = 반지름 × 회전속도² (radius·wr²)4배 (제곱)

표시용으로 velLen = clamp(v·5.5, 22, 88), forLen = clamp(a·72, 18, 반지름·0.82)(힘 화살표가 중심을 넘지 않도록 상한). 회전속도를 키우면 🔵는 비례, 🔴는 제곱으로 길어져 고속에선 힘 화살표가 속도 화살표를 추월한다 — "빨리 돌릴수록 줄을 훨씬 더 세게 잡아야 한다"가 눈에 보인다. 가변 길이로 라벨이 화면을 벗어날 수 있어 tag()에 캔버스 내 위치 클램프를 추가했다. 1단계에 v=R×회전속도 / 힘=R×회전속도²(2배→4배, 회전 놀이기구 비유) .tip.bonus를 추가하고, 화살표 라벨을 '관성'→'속도'로 바꿔 크기 의미를 분명히 했다.
