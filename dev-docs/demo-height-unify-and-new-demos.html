데모 높이 통일 · 6편 오버레이 버그 · 3·11편 신규 데모

작성일 2026-06-02 관련 PR #31 대상: entry-game-1·2·3·6·7·11 + assets/styles.css

사용자 피드백 4가지(높이 일부만 반영·6편 흰 오버레이·데모 없는 편·11편 스프링 연관 설명만)를 한 사이클에 해결 — 캔버스 높이를 전 편 400으로 통일하고 빈 하늘에 구름 배경을 채우고, 6편 시작 오버레이 버그를 고치고, 3편(관성)·11편(스프링→원운동) 데모 2개를 신규 추가했다.

TL;DR
  • 높이 통일: 가로 액션을 일부러 낮게(1·2편 300, 6·7편 360) 뒀던 차등 설계를 거두고 전 편 400으로 통일. 늘어난 상단 하늘은 각 데모의 drawClouds() 구름으로 채워 휑함 방지(직전 PR #30의 미해결 TODO 해소).
  • 6편 버그: togglePush()에서 updateBtn()이 startLoop()보다 먼저 호출돼 running=false 상태로 idle 토글이 평가 → 흰 ‘시작 대기’ 오버레이가 시작 후에도 잔류. 두 줄 순서를 바꿔 해결(5·7편 정상 패턴과 동일).
  • 3편 데모 신규: 11편 중 유일하게 데모가 없던 3편(관성)에 밀기→관성 미끄러짐→표면별 마찰 정지 데모 추가. 표면 4종(모래 0.7·잔디 0.85·빙판 0.95·우주 1.0)은 같은 페이지 마찰 섹션 값과 정렬, 우주=마찰0이 2편의 ‘안 멈추는 문제’를 시연.
  • 11편 데모 신규: ‘구심력 = 10편 복원력’ 한 문장 설명을 전용 데모로 구체화. 같은 중심 당기는 힘을 x·y 양쪽에 걸어 옆 속도 0이면 직선 진동(=10편), 적당하면 원운동. 회전 코일(=용수철)+구심력 화살표 시각화.
  • preview MCP eval로 전 편 검증: canvas.height=400·구름 픽셀·6편 idle 제거·3·11편 신규 데모 배선·콘솔 에러 0.

개요

직전 PR #30(demo-canvas-width-height-touch.html)에서 데모 캔버스를 본문 폭에 맞추고 높이를 장면별로 키웠다. 그 뒤 사용자가 네 가지를 지적했고, 이번 사이클에서 한 번에 처리했다.

이슈
  • 높이가 일부만 늘어난 듯 — 사실 가로 액션(1·2편 300, 6·7편 360)을 세로/2D 액션(400)보다 일부러 낮게 둔 차등 설계였다. 사용자는 통일을 원함.
  • 6편 흰 오버레이 잔류 — ‘힘과 질량’ 데모가 흰 ‘시작 대기’ 화면으로 시작하는데, ▶ 밀기를 눌러도 그 흰 막이 사라지지 않음.
  • 데모 없는 편 — 게임 11편 중 3편(관성)만 캔버스 데모가 없음.
  • 11편 스프링 연관 설명이 한 문장 — ‘구심력 = 10편 복원력’을 tip 박스 한 문단으로만 설명해 이해가 어려움(데모 없음).

해결 1 — 캔버스 높이 400 통일 + 빈 하늘 구름

캔버스는 width:100%; height:auto로 표시돼 가로는 본문 폭에 고정되므로, height 속성만 키우면 표시 세로가 비례해 커진다(왜곡 없음). PR #30에서 가로 액션을 ‘빈 하늘 과다 방지’로 낮춰 뒀는데, 이번엔 그 우려를 구름으로 채우는 방식으로 흡수하고 전 편을 400으로 맞췄다.

편액션 성격height (PR #30 → 이번)구름 배경
1편 이동가로+점프300 → 400추가
2편 가속가로300 → 400추가
6편 힘·질량가로360 → 400추가
7편 충돌가로360 → 400추가
4·5·8·9·10·11편세로/2D400 (유지)해당 없음(앵커 가득)
3편 관성(신규)가로— → 400추가

모든 데모가 drawGround() 첫 줄에서 ctx.clearRect(0,0,W,H)로 캔버스를 비우고 하늘 영역은 투명으로 남겨 CSS 그라데이션(--sky1/--sky2)이 비치는 구조다. 늘어난 상단을 채우기 위해 clearRect 직후 drawClouds()를 호출하도록 했다(바닥·객체·HUD보다 뒤에 깔림).

function drawClouds(){              // 1·2·3·6·7편 공통(저채도 정적 구름)
  const puff = (cx, cy, s, a) => {
    ctx.fillStyle = 'rgba(255,255,255,' + a + ')';
    ctx.beginPath();
    ctx.ellipse(cx, cy, s, s * 0.62, 0, 0, Math.PI * 2);
    ctx.ellipse(cx - s * 0.82, cy + s * 0.20, s * 0.64, s * 0.48, 0, 0, Math.PI * 2);
    ctx.ellipse(cx + s * 0.82, cy + s * 0.20, s * 0.64, s * 0.48, 0, 0, Math.PI * 2);
    ctx.fill();
  };
  puff(W * 0.16, 66, 30, .52); puff(W * 0.82, 50, 23, .42); puff(W * 0.50, 118, 18, .28);
}
function drawGround(){ ctx.clearRect(0,0,W,H); drawClouds(); /* …기존 바닥… */ }
왜 7편도 구름인가

당구 7편도 다른 가로 데모와 똑같은 sky 그라데이션 + 갈색 바닥 구조라(공이 바닥 위를 구름) 별도 펠트 처리 없이 같은 구름으로 일관 적용했다. 계획 단계에선 7편 특수 처리를 열어 뒀으나 실제 코드가 동형이라 통일이 더 단순·일관적.

해결 2 — 6편 ‘시작 대기’ 오버레이 잔류 버그

흰 오버레이는 .try-focus-msg(rgba(255,255,255,.55)) DOM 요소로, 부모 .try-canvas-wrap.idle일 때만 opacity:1이다. updateBtn()은 wrap.classList.toggle('idle', !running && !success)로 idle을 토글한다.

원인 & 해결

togglePush()가 updateBtn()를 먼저 부르고 startLoop()(여기서 running=true)를 나중에 불렀다. 그래서 idle 토글이 평가되는 순간 running이 아직 false → idle 유지 → 흰 막 잔류. 두 줄의 순서를 바꿔 running=true가 먼저 켜지도록 했다(5편 setRunning()·7편 launch()의 정상 패턴과 동일).

Before — idle 잔류

function togglePush(){
  if (success) return;
  pushing = !pushing;
  updateBtn();   // running=false 상태
  startLoop();   // 여기서야 running=true
}

After — 시작 시 오버레이 제거

function togglePush(){
  if (success) return;
  pushing = !pushing;
  startLoop();   // running=true 선설정
  updateBtn();   // idle 토글이 올바르게 평가
}

해결 3 — 3편 관성·마찰 데모 신규

3편은 게임 11편 중 유일하게 캔버스 데모가 없었다. 2편의 .try-demo/.try-pad 구조를 베이스로(페이지 로컬 데모 CSS는 --c3 보라로 재색해 신규 추가) .goals 박스 다음에 데모 우선 섹션을 넣었다.

핵심은 2편 루프(vel += accel; heroX += vel — 마찰이 없어 안 멈춤)에 vel *= friction을 더한 것이다. 꾹 눌러 밀다 떼면 관성으로 미끄러지다 마찰로 멈춘다. 표면 4종은 같은 페이지 마찰 섹션의 마찰계수·라벨과 정확히 정렬했고, 표면에 따라 바닥 색도 바뀐다.

표면마찰계수체감(떼었을 때)
🏜️ 모래밭0.7거의 못 미끄러지고 금방 멈춤
🌿 잔디밭(기본)0.85적당히 미끄러지다 멈춤
🧊 빙판0.95쭉 미끄러짐
🚀 우주1.0벽에 닿을 때까지 안 멈춤 = 2편의 ‘안 멈추는 문제’ = 순수 관성
속도 캡으로 표면 비교를 선명하게

강한 마찰(0.7~0.95)+미는 힘이면 표면별 최고 속도(PUSH/(1−fr))가 제각각이라, MAXV=10으로 캡해 ‘미끄러지는 거리’ 차이에 집중하게 했다. 우주(1.0)는 감속이 없어 캡 속도로 등속 → 벽까지 직진(뉴턴 1법칙).

해결 4 — 11편 스프링→원운동 연결 데모 신규

구심력 섹션의 ‘구심력 = 10편 복원력’ 설명(tip 한 문단)을 전용 데모로 구체화해, 위키 정의 tip과 ‘현실은 타원’ tip 사이에 넣었다(타원 tip이 데모의 타원 거동을 바로 설명).

핵심 아이디어

10편 스프링 힘 force=(restY−y)·k를 x·y 양쪽으로 일반화: 매 프레임 vx += K·(cx−bx); vy += K·(cy−by). 힘은 항상 중심을 향하고(=복원력=구심력), 옆으로 미는 처음 속도만 다르다 — 0이면 직선 진동(10편 스프링을 눕힌 모습), 딱 맞으면(R·√K) 동그란 원운동. 같은 식인데 시작 속도가 운동을 가른다.

  • 회전 코일: 중심↔공을 잇는 용수철 코일(10편 drawSpring 지그재그를 rotate로 임의 방향에 그림) = ‘중심으로 당기는 힘’의 시각적 정체.
  • 구심력 화살표: 공에서 중심 방향으로 항상 향하는 빨간 화살표.
  • 모드 토글(.mode-pick, --c11): ↕ 직선 진동 / 🌀 원운동. 가이드도 모드에 맞춰 직선/원으로 바뀌고, 자취(trail)가 선 vs 원을 그려 전환을 증명.
  • 기존 원운동 데모(demoCanvas11)와 충돌 없게 별도 IIFE(demoCanvasLink11)로 추가.
정확성 — 선형 복원력은 타원

2D 선형 복원력(F=−k·r)의 궤도는 일반적으로 중심 타원이고 딱 맞는 속도일 때만 원이다. 이는 같은 섹션의 .tip.real(현실 = 타원, 게임 = 반지름 고정+각도 증가로 깔끔한 원)이 이미 설명하므로, 데모를 그 tip 바로 앞에 배치해 자연스럽게 이어지게 했다.
